# 법인세 분석 보고서 자동화

같은 회사의 전기·당기 **세무조정계산서 PDF 2개**를 읽어 **법인세 분석 보고서(PDF)** 를 만드는 Python 프로그램입니다. Forward Fellowship 6주차 실습(고객: 샘플세무법인)에서 만들었고, 실습 1~4차를 모두 통과했습니다.

보고서의 모든 숫자에는 출처(파일·서식·쪽·서식 코드)가 붙고, 읽지 못했거나 기준이 정해지지 않은 값은 확정값처럼 쓰지 않고 «가정» 또는 «확인 필요»로 구분해 적습니다.

## 빠른 시작

[uv](https://docs.astral.sh/uv/)와 Python 3.12 이상이 필요합니다.

```bash
uv sync
uv run taxreport build <전기.pdf> <당기.pdf> --out output/
```

`output/`에 두 파일이 생깁니다.

- `{회사명}_{당기연도}_법인세분석보고서.pdf`
- `{회사명}_{당기연도}_추출결과.json` — 추출한 값과 출처 전체

두 PDF의 순서는 상관없습니다. 전기·당기는 파일명이 아니라 PDF 본문의 사업연도로 판정합니다. 회사가 다르거나 사업연도가 이어지지 않으면 이유를 알리고 멈춥니다.

PDF 하나에서 무엇을 읽었는지 확인하려면:

```bash
uv run taxreport inspect <PDF>
```

### 한글 글꼴

보고서 PDF에는 한글 글꼴이 필요합니다. 다음 순서로 찾고, 없으면 오류로 멈춥니다(글자가 깨진 PDF를 만들지 않습니다).

1. `assets/fonts/*.ttf`
2. `policy.yaml`의 `font_path`
3. macOS의 `AppleGothic.ttf`

macOS가 아니면 한글 TTF 파일을 `assets/fonts/`에 넣어 주세요.

## 보고서 내용

1. 주요 지표 비교 — 매출액·영업이익·당기순이익·부채비율의 전기/당기/증감
2. 그래프 4종 — 주요 손익, 판관비 구성비율, 판관비 주요 항목, 재무상태
3. 요약 코멘트 — 정해 둔 문장 틀에 수치를 넣어 만듭니다(LLM 호출 없음)
4. 요약 손익 비교 — 원 단위, 증감액과 증감률
5. 판관비 주요 항목 — 주요 5개 + 기타, 매출액 대비 비중
6. 세무조정 특이사항 — 소득금액조정, 이월결손금, 공제·감면, 과세표준과 세액
7. 재무제표 주요 특이사항
8. 가정·확인 필요 목록
9. 근거 목록 — 값마다 파일·서식·쪽·서식 코드

## 지원하는 입력

| 출력 프로그램 | 표준서식 금액 표기 | 상태 |
|---|---|---|
| 위하고(더존) | 칸마다 `:` (`21:224:676`) | 지원 |
| 세무사랑 | 쉼표 숫자 (`2,801,777,825`) | 지원. 부속명세서의 거래처별 잔액과 결손금 내역은 아직 읽지 못함 |

글자 정보가 있는 PDF만 읽습니다. 스캔본(이미지 PDF)은 지원하지 않습니다.

재무 숫자는 **표준재무상태표와 표준손익계산서**에서만 읽습니다(고객 확정 사항). 같은 항목인지는 항목 이름이 아니라 서식 코드로 판단합니다.

## 값을 다루는 원칙

- **가려진 칸은 0이 아닙니다.** 회색으로 가려졌거나 금액 대신 «확인중» 같은 글자가 있는 칸은 값 없이 «확인 필요»로 두고, 그 값에 의존하는 계산만 보류합니다.
- **서식끼리 숫자가 다르면 덮어쓰지 않습니다.** 같은 범위의 값인지 먼저 보고, 차이를 경고로 남깁니다.
- **고객이 정하지 않은 기준은 가정입니다.** `src/taxreport/config/policy.yaml`에 모아 두었고 보고서의 «가정» 목록에 적힙니다.
- **회사별 값을 코드에 넣지 않습니다.** 회사명, 쪽 번호, 금액은 PDF에서 읽고, 서식 인식 규칙은 `src/taxreport/config/forms.yaml`에 있습니다.

## 구조

```
src/taxreport/
  cli.py        진입점 (build, inspect)
  config/       policy.yaml(정책·문구), forms.yaml(서식 인식 규칙·항목 코드)
  render/       보고서 PDF, 그래프, 표기 형식
  analyze/      지표, 비교, 판관비, 특이사항, 코멘트
  extract/      PDF 읽기, 접수 검증, 서식 색인, 서식별 추출, 산식 검증
  domain/       모델 (값 + 상태 + 출처)
tests/
```

의존 방향은 `cli → render → analyze → extract → domain` 한쪽으로만 흐르고, `tests/test_architecture.py`가 이를 검사합니다.

## 개발

```bash
uv run pytest -q                          # 전체 테스트
uv run pytest tests/test_x.py::test_name  # 단일 테스트
uv run ruff check .
uv run mypy src --strict
```

샘플 PDF는 저장소에 없습니다. 기준값 테스트는 저장소 루트에 `샘플컴퍼니_2024_세무조정계산서.pdf`, `샘플컴퍼니_2025_세무조정계산서.pdf`가 있을 때만 실행되고 없으면 건너뜁니다.

읽는 규칙을 고쳤다면 이전에 통과한 자료를 모두 다시 실행해 보고서가 달라지지 않았는지 비교합니다.
