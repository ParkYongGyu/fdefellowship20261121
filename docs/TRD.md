- 작성일: 2026-11-21
- 상태: 초안 (구현 전 확인용)
- 고객: 샘플세무법인
- 관련 문서: `CLAUDE.md`(실습 규칙·PDF 구조), `claudedocs/1차_질문지.md`(고객 질의·답변 원문)

## 1. 목적과 범위

같은 회사의 전기·당기 세무조정계산서 PDF 2개를 받아 **법인세 분석 보고서(PDF·Excel)** 와 **조정료청구서** 를 만든다. 세무법인 실무자 한 명이 신고 시즌에 최대 20개 법인을 회사만 바꿔 반복 처리하고, 담당 세무사가 숫자의 출처를 확인한 뒤 고객사에 보낸다.

실습은 1~4차로 진행되고 차수마다 새 자료가 온다. 같은 프로그램을 계속 고쳐 쓴다. 채점 대상은 최종 분석 보고서 PDF 하나다.

| 구분 | 내용 |
|---|---|
| 1차 포함 | PDF 2개 접수·검증, 값 추출(출처 포함), 지표 계산, 보고서 PDF, 보고서 Excel, 조정료청구서 초안, CLI |
| 1차 제외 | 웹 화면, 여러 법인 일괄 처리, 스캔본(OCR), 위하고 외 프로그램 출력물, Excel 수정본 → PDF 재생성 |

### 설계 원칙

1. **모든 숫자는 출처와 함께 다닌다.** 값마다 (파일, 서식, 페이지, 서식 코드)를 붙이고, 보고서의 근거 목록은 여기서 자동으로 만든다.
2. **확정·가정·확인 필요를 구분한다.** 고객이 정하지 않은 기준은 가정으로 계산하고 보고서에 가정임을 적는다. 값을 읽지 못했을 때만 «확인 필요»로 출력한다(«확인 필요»는 채점에서 오답).
3. **회사에 종속된 값을 코드에 두지 않는다.** 회사명, 페이지 번호, 계정 목록은 PDF에서 읽고, 정책과 문구는 설정 파일에 둔다.
4. **페이지 번호가 아니라 서식 제목으로 찾는다.** 연도마다 들어 있는 서식과 쪽수가 다르다.

## 2. 확정된 요구사항과 가정

### 2.1 고객이 확정한 것

| # | 내용 |
|---|---|
| R1 | 출력 예시 Excel은 모양만 참고한다. 숫자는 받은 회사 자료(PDF)에서 가져온다. |
| R2 | 보고서에서 부가가치세 신고내용과 원천징수이행상황은 뺀다. |
| R3 | 재무 숫자는 그 사업연도의 **표준재무상태표·표준손익계산서** 기준이다. 결산서 숫자로 바꿔 넣지 않는다. |
| R4 | 주요지표는 1억 이상이면 소수 둘째 자리 억원(예: 1.93억원), 1억 미만이면 만원 단위(예: 4,900만원)로 쓴다. |
| R5 | 판관비 주요 항목은 5개로 고정하고 나머지는 «기타»로 묶는다. |
| R6 | 전기 적자 → 당기 흑자는 «흑자전환»으로 쓴다. «적자전환»·«적자지속»은 쓰지 않는다. |

요구사항 Excel에서 그대로 따르는 것: 주요지표 4종(매출액·영업이익·당기순이익·부채비율)의 전기/당기/증감, 그래프 4종, 요약 코멘트, 요약 손익 비교(원 단위, 증감액·증감률), 판관비 주요 항목(원 단위, 증감액, 매출액 대비 비중), 세무조정 특이사항, 재무제표 특이사항, «샘플세무법인 발행» 표기.

실습 채점 조건: 보고서에 회사 이름·사업연도·항목 이름이 보여야 하고, 표의 열 제목에 연도를 적으며, 금액을 줄여 쓸 때 단위를 표시한다.

## 3. 기술 스택

| 용도 | 선택 | 이유 |
|---|---|---|
| 패키지·실행 | `uv`, Python ≥ 3.12 | harness 표준 |
| PDF 읽기 | `pdfplumber` | 순수 Python. 단어별 좌표를 주므로 좌우 2단인 표준서식에서 코드 번호 옆 금액을 찾기 쉽다 |
| 데이터 모델 | `pydantic` v2 | 경계에서 파싱 |
| 보고서 PDF | `reportlab` (platypus) | 순수 Python. 한글 TTF를 임베드하면 글자로 추출된다(자동 채점이 PDF 글자를 읽음) |
| 그래프 | `matplotlib` | 막대·원그래프를 이미지로 삽입 |
| Excel | `openpyxl` | 수기 수정용 출력 |
| 설정 | `pyyaml` | 정책·서식 규칙 |
| 로깅 | `structlog` | 구조화 로깅 |
| CLI | `argparse` | 표준 라이브러리 |
| 품질 | `ruff`, `mypy --strict`, `pytest` | harness Phase 5 검증 |

**한글 글꼴**: 고객 지정 글꼴이 미정이라 경로를 설정값으로 둔다. 탐색 순서는 `assets/fonts/*.ttf` → `policy.yaml`의 `font_path` → macOS `/System/Library/Fonts/Supplemental/AppleGothic.ttf`. 찾지 못하면 오류로 멈춘다(글자가 깨진 PDF를 만들지 않는다). 글꼴 파일은 저장소에 넣지 않는다. matplotlib에도 같은 글꼴을 등록한다.

**추출 라이브러리 검증**: 지금까지의 자료 분석은 `pdftotext -layout`으로 했다. 구현 첫 단계에서 `pdfplumber` 결과를 `CLAUDE.md`의 기준값과 대조하고, 맞지 않으면 파싱 규칙을 조정한다.

### 레이어 규칙

의존 방향은 `cli → render → analyze → extract → domain` 한쪽으로만 흐른다.

- `domain`: 모델만 둔다. 파일·PDF·설정을 읽지 않는다.
- `extract`: PDF에서 `Filing`을 만든다. 계산·판단을 하지 않는다.
- `analyze`: `Filing` 두 개로 `Report`를 만든다. PDF·파일 출력을 모른다.
- `render`: `Report`를 PDF·Excel로 그린다. 값을 새로 계산하지 않는다(표시 형식만 적용).
- `config`: 모든 레이어가 읽을 수 있다. `config`는 `domain`만 import한다.

이 규칙은 `tests/test_architecture.py`가 각 모듈의 import를 검사해 강제한다. `print()`는 `cli.py`의 최종 결과 출력 외에는 쓰지 않는다.

## 5. 데이터 모델 (`domain/models.py`)

```python
class Source(BaseModel):
    file: str            # PDF 파일명
    form: str            # 서식명 (예: 표준손익계산서)
    page: int            # 1부터 시작하는 PDF 쪽
    code: str | None     # 서식 코드 (예: "129")
    label: str | None    # 원문 항목명

class ValueStatus(StrEnum):
    CONFIRMED = "확정"
    ASSUMED = "가정"
    NEEDS_CHECK = "확인 필요"

class SourcedValue(BaseModel):
    value: Decimal | None
    status: ValueStatus
    source: Source | None    # 계산값은 sources 목록으로 대체
    derived_from: list[Source] = []
    note: str | None = None

class CompanyIdentity(BaseModel):
    name: str                # 원문 표기 (예: (주)샘플컴퍼니)
    business_no: str         # 사업자등록번호
    period_start: date
    period_end: date
    fiscal_year: int         # period_end의 연도

class LineItem(BaseModel):   # 표준서식의 한 줄
    code: str
    label: str
    amount: SourcedValue
    parent_code: str | None

class Filing(BaseModel):     # 한 사업연도의 추출 결과
    identity: CompanyIdentity
    balance_sheet: dict[str, LineItem]      # 코드 → 항목
    income_statement: dict[str, LineItem]
    tax: TaxSummary                          # 과세표준, 산출세액, 감면, 총부담세액, 이월결손금 ...
    adjustments: list[TaxAdjustment]         # 소득금액조정 항목
    credits: list[TaxCredit]                 # 공제·감면
    schedules: Schedules                     # 외상매출금·가수금 등 거래처별 잔액
    forms_found: list[FormRef]               # 발견한 서식과 쪽
    warnings: list[str]

class CompanyCase(BaseModel):
    prior: Filing
    current: Filing

class Report(BaseModel):     # 표시용 데이터
    company: str
    prior_year: int
    current_year: int
    issuer: str
    key_metrics: list[MetricRow]
    income_comparison: list[ComparisonRow]
    sga_items: list[SgaRow]
    comments: list[CommentBlock]
    tax_notes: list[Note]
    financial_notes: list[Note]
    assumptions: list[str]
    needs_check: list[str]
    evidence: list[EvidenceRow]   # 항목, 연도, 값, 파일, 서식, 쪽
```

금액은 모두 `Decimal`(원 단위)로 보관한다. 억원·만원·% 표기는 `render/formatters.py`에서만 한다.

## 6. 처리 흐름

### 6.1 접수 (`extract/intake.py`)

1. 각 PDF에서 «법인세과세표준및세액신고서»(별지 제1호서식)를 찾아 법인명, 사업자등록번호, 사업연도를 읽는다.
2. 두 파일의 사업자등록번호가 같은지, 사업연도가 연속인지(전기 종료일 다음 날 = 당기 시작일) 검증한다.
3. 전기·당기는 **파일명이나 인자 순서가 아니라 사업연도**로 판정한다.
4. 실패하면 이유를 밝히고 멈춘다: 회사가 다름, 같은 연도 두 개, 연도가 이어지지 않음, 신고서를 찾지 못함.

### 6.2 서식 색인 (`extract/form_index.py`)

- 페이지 앞부분 텍스트에서 공백을 제거한 뒤 `forms.yaml`의 제목 패턴과 맞춰 서식을 식별한다.
- «(4쪽중제2쪽)»처럼 이어지는 쪽은 앞 서식에 붙인다.
- 같은 제목이 법정 서식과 결산보고서에 모두 있으면(재무상태표 / 표준재무상태표) 더 구체적인 패턴을 먼저 적용한다.
- 결과: `서식명 → [쪽 번호]`. 없는 서식은 오류가 아니라 «없음»으로 기록한다.

### 6.3 값 추출

**표준재무상태표·표준손익계산서 (`standard_forms.py`)** — 재무 숫자의 유일한 출처(R3).

- 한 줄에 좌우 두 단(항목명·코드·금액)이 나란히 있다. 쪽의 가운데를 기준으로 단을 나누고, 각 단에서 «항목명 … 코드 … 금액» 줄을 읽는다.
- 금액 칸은 자릿수 구분이 `:`로 나온다: `21:224:676`, `:2:021:410`, `-15:385:718`, 빈 칸은 `:`. 구분 기호를 제거하고 부호를 살려 `Decimal`로 바꾼다.
- 코드가 있는 모든 줄을 읽어 `dict[코드, LineItem]`으로 보관한다(판관비 세부 항목을 쓰기 위해).
- 필수 코드:

| 서식 | 항목 | 코드 |
|---|---|---|
| 표준손익계산서 | 매출액 / 매출원가 / 매출총손익 | 1 / 35 / 66 |
| | 판매비와관리비 / 영업손익 | 67 / 129 |
| | 영업외수익 / 영업외비용 | 130 / 179 |
| | 법인세비용차감전손익 / 법인세비용 / 당기순손익 | 217 / 218 / 219 |
| 표준재무상태표 | 유동자산 / 비유동자산 / 자산총계 | 1 / 80 / 228 |
| | 유동부채 / 비유동부채 / 부채총계 | 229 / 284 / 333 |
| | 자본금 / 이익잉여금 / 자본총계 | 334 / 372 / 382 |

- 판관비 세부 항목은 코드 68~128 범위에서 읽는다. «1.급여»(68)와 그 아래 «나.직원급여»(70)처럼 상위·하위가 함께 있으면 상위 항목만 주요 항목 후보로 쓴다(이중 계산 방지).

**세무 서식 (`tax_forms.py`)**

| 서식 | 읽는 값 | 없을 때 |
|---|---|---|
| 법인세과세표준및세액조정계산서 | 결산서상 당기순손익(01), 익금산입(02), 손금산입(03), 각 사업연도 소득금액(06), 이월결손금(07), 과세표준(10), 세율(11), 산출세액(12), 최저한세 적용대상 공제감면세액(17), 총부담세액 | 확인 필요 |
| 소득금액조정합계표 | 과목, 금액, 소득처분 | 조정 사항 없음 |
| 공제감면세액및추가납부세액합계표(갑) | 구분, 근거 법조항, 감면세액 (금액이 있는 줄만) | 공제·감면 없음 |
| 최저한세조정계산서 | 감면후세액, 최저한세 | 해당 없음 |
| 자본금과적립금조정명세서(갑) | 사업연도별 결손금 발생액·잔액 | 해당 없음 |

**결산 부속명세서 (`schedules.py`)** — 특이사항에만 쓴다.

- 외상매출금명세서, 가수금명세서, (있으면) 가지급금·대여금명세서의 거래처별 기말 잔액.
- 연도마다 열 구성이 다르다(2024는 금액 한 열, 2025는 기초·증가·감소·금액). 맨 오른쪽 금액 열을 기말 잔액으로 읽는다.
- 합계 행은 숫자 안에 공백이 끼는 경우가 있어(`7,3 24,268`) 합계는 거래처별 금액을 더해 구하고, 표준재무상태표의 해당 계정과 대조한다.

### 6.4 검증 (`extract/checks.py`)

- 자산총계 = 부채총계 + 자본총계
- 매출액 − 매출원가 = 매출총손익, 매출총손익 − 판관비 = 영업손익
- 법인세비용차감전손익 − 법인세비용 = 당기순손익
- 판관비 세부 항목 합 = 판관비
- 세액조정계산서의 결산서상 당기순손익 = 표준손익계산서의 당기순손익

어긋나면 `Filing.warnings`에 남기고 보고서의 «확인 필요 목록»에 적는다. 값은 서식에 적힌 그대로 쓴다(프로그램이 고치지 않는다).

### 6.5 분석 (`analyze/`)

- `metrics.py`: 주요지표 4종과 부채비율.
- `comparison.py`: 증감액, 증감률, 흑자전환 판정.
- `sga.py`: 판관비 주요 항목 선정(당기 상위 N개), 나머지 «기타» 합산, 매출액 대비 비중, 구성비.
- `notes.py`: 세무조정 특이사항, 재무제표 특이사항(규칙 기반).
- `comments.py`: 요약 코멘트(문장 틀).
- `builder.py`: 위 결과를 모아 `Report`를 만든다.

### 6.6 출력 (`render/`)

`Report` 하나로 보고서 PDF, 보고서 Excel, 조정료청구서를 만든다.

## 7. 보고서 규칙

### 7.1 구성

1. 머리말: «법인세 분석 보고서», 회사명, 사업연도(전기·당기 기간), 발행자 «샘플세무법인», 작성일
2. 주요 지표 비교
3. 그래프 4종
4. 요약 코멘트
5. 요약 손익 비교
6. 판관비 주요 항목
7. 세무조정 특이사항
8. 재무제표 주요 특이사항
9. 가정·확인 필요 목록
10. 근거 목록 (항목 / 연도 / 값 / 파일 / 서식 / 쪽)

모든 쪽의 꼬리말에 «샘플세무법인 발행»과 회사명·쪽 번호를 넣는다. 회사명은 PDF 원문 표기를 그대로 쓴다.

### 7.2 주요 지표 비교

열: 구분 / {전기연도}년(전기) / {당기연도}년(당기) / 증감.

| 항목 | 표기 |
|---|---|
| 매출액·영업이익·당기순이익 | 절댓값 1억 이상 → `1.93억원`, 1억 미만 → `4,925만원`. 음수는 `-1,539만원`. 증감액도 같은 규칙 |
| 부채비율 | `51.79%`. 자본총계가 음수면 `자본잠식 (-354.88%)` |

표 아래에 «단위: 1억원 이상은 억원, 1억원 미만은 만원»을 적는다.

### 7.3 그래프

| 그래프 | 종류 | 데이터 |
|---|---|---|
| 전기·당기 주요 손익 비교 | 묶은 막대 | 매출액, 영업이익, 당기순이익 |
| 판관비 구성비율 | 원그래프(% 표시) | 당기 주요 5개 + 기타 |
| 판관비 주요 5개 항목 전기·당기 비교 | 묶은 막대 | 주요 5개 |
| 재무상태 비교 | 묶은 막대 | 자산총계, 부채총계, 자본총계 |

축 제목에 단위를, 범례에 연도를 적는다. 그래프의 값은 표에도 글자로 있어야 한다(채점은 글자를 읽는다).

### 7.4 요약 손익 비교

단위: 원. 열: 구분 / 전기 / 당기 / 증감액 / 증감률.

행: 매출액, 매출총이익, 영업손익, 영업외수익, 영업외비용, 법인세차감전손익, 법인세비용, 당기순이익.

증감률 = (당기 − 전기) ÷ |전기| × 100, 소수 첫째 자리. 예외는 순서대로 적용한다.

1. 전기 < 0이고 당기 > 0 → «흑자전환»
2. 전기 = 0 → «-»
3. 전기 < 0 또는 당기 < 0(그 외 조합) → «-»
4. 나머지 → 계산값

### 7.5 판관비 주요 항목

단위: 원. 열: 항목 / 전기 금액 / 당기 금액 / 증감액 / 전기 매출액 대비 비중 / 당기 매출액 대비 비중.

행: 주요 5개 + «기타» + «판매비와관리비 합계». 주요 5개 + 기타 = 합계가 되도록 «기타»는 합계에서 주요 5개를 뺀 값으로 계산한다. 전기 금액은 같은 서식 코드로 전기 표준손익계산서에서 찾고, 없으면 0으로 쓴다.

### 7.6 세무조정 특이사항 (규칙)

- 소득금액조정 항목마다: «{과목} {금액}원을 {익금산입·손금불산입 / 손금산입·익금불산입}하고 {소득처분}으로 처분했습니다.»
- 조정 항목이 없으면: «{연도}년은 세무조정 사항이 없습니다.»
- 이월결손금 공제액이 있으면 금액과 발생 사업연도.
- 공제·감면이 있으면 구분명, 근거 법조항, 감면세액.
- 과세표준, 산출세액, 총부담세액 요약.
- 서식 간 금액이 다르면(예: 전기 과세표준 결손액과 이월결손금 발생액) 두 값을 모두 적고 «확인 필요»로 표시한다.

### 7.7 재무제표 주요 특이사항 (규칙)

| 규칙 | 조건 | 문장에 넣는 값 |
|---|---|---|
| 자본잠식 | 자본총계 < 0 | 자본총계, 해소 여부(전기 잠식 → 당기 해소) |
| 가수금 | 주주·임원·직원단기차입금 또는 가수금명세서 잔액 > 0 | 전기·당기 잔액, 감소액 |
| 가수금 정리 필요액 | 당기 자본총계 < 0 | 자본총계의 절댓값(가정임을 명시) |
| 가지급금 | 주주·임원·직원 대여금 잔액 > 0 | 잔액, 매출액 대비 비율 |
| 외상매출금 | 잔액 있음 | 전기·당기 잔액, 매출액 대비 비율, 잔액이 있는 거래처 수 |
| 부채비율 | 항상 | 전기·당기 부채비율 |

해당 계정이 없는 규칙은 문장을 만들지 않는다. «대폭 증가» 같은 판단 표현은 기준이 미정이므로 쓰지 않고 수치만 적는다.

### 7.8 요약 코멘트 (문장 틀)

항목: ① 매출 및 수익성 ② 판관비 주요 항목 ③ 영업외손익 ④ 전년 대비 주요 변동 ⑤ 재무비율(부채비율) ⑥ 공제·감면. 각 2~3문장, 문장 틀은 `policy.yaml`에 둔다. 영업외손익은 금액이 있는 계정명과 금액만 적는다(PDF에 사유가 없다). «주요 변동»은 증감액 절댓값이 큰 손익 항목과 판관비 항목을 고른다.

## 8. Excel과 조정료청구서

**보고서 Excel** (`report_xlsx.py`): 시트 — 주요지표, 요약손익비교, 판관비, 요약코멘트, 세무조정, 재무제표특이사항, 가정·확인필요, 근거. 금액은 숫자 셀로 넣어 수기 수정과 계산이 가능하게 한다.

**조정료청구서** (`invoice.py`): 채점 대상이 아니므로 가장 나중에 만든다.

- 기준금액: 매출액, 자산총계, 자산총계의 1/2를 모두 적는다. «매출액과 자산의 1/2 중 큰 금액»의 해석이 미정이므로 두 해석의 값을 함께 보여 주고 «확인 필요»로 둔다.
- 공제·감면액: 추출한 감면세액을 적는다.
- 보수 금액, 가산액, CMS 출금일, 피드백 요청일: 보수표·가산율·날짜가 미정이므로 «확인 필요». `policy.yaml`에 보수 구간표·가산율·날짜를 넣을 자리를 만들어 두고, 값이 있으면 계산한다.

## 9. 설정 파일

`policy.yaml` (예):

```yaml
issuer:
  name: 샘플세무법인
  footer: 샘플세무법인 발행
units:
  eok_threshold: 100000000
  eok_decimals: 2
  rounding: half_up        # 가정 A1
debt_ratio:
  decimals: 2
  negative_equity_label: 자본잠식
sga:
  top_n: 5                 # 확정 R5
  other_label: 기타
  selection: current_amount_desc   # 가정 A8
comparison:
  turnaround_label: 흑자전환       # 확정 R6
  not_applicable: "-"
font_path: null
invoice:
  fee_table: []            # 미정
  credit_surcharge: []     # 미정
  cms_withdrawal_day: null
  feedback_due_day: null
```

`forms.yaml`: 서식별 제목 패턴과 항목 코드. 새 서식이나 다른 양식이 들어오면 이 파일에 규칙을 추가한다.

## 10. CLI

```
uv run taxreport build <PDF1> <PDF2> [--out output/] [--policy path] [--skip-invoice]
uv run taxreport inspect <PDF>      # 서식 색인과 추출값·출처를 출력 (검토용)
```

`build`의 출력: `output/{회사명}_{당기연도}_법인세분석보고서.pdf`, `…_법인세분석보고서.xlsx`, `…_조정료청구서.xlsx`, `…_추출결과.json`. 끝에 가정·확인 필요 건수를 요약해 보여 준다. 접수 검증에 실패하면 0이 아닌 종료 코드로 끝낸다.

## 13. 위험과 확장 지점

| 위험 | 영향 | 대응 |
|---|---|---|
| `pdfplumber`의 추출 결과가 분석 때 쓴 `pdftotext`와 다름 | 표준서식 파싱 실패 | M1에서 기준값 대조. 좌표 기반 단 분리로 조정 |
| 가정이 채점 기준과 다름(판관비 선정, 반올림, 부채비율 표기) | 일부 항목 오답 | 모든 가정을 `policy.yaml`로 분리. 채점 피드백을 보고 설정만 변경 |
| 2~4차에서 다른 회사·다른 서식 구성이 들어옴 | 추출 누락 | 제목 기반 색인, 없는 서식은 «없음» 처리, `inspect` 명령으로 빠르게 확인 |
| 한글 글꼴이 없는 환경 | PDF 글자 깨짐 | 글꼴을 찾지 못하면 오류로 중단 |
| 서식 간 숫자 불일치(이월결손금 129,800원 차이 등) | 잘못된 값 선택 | 임의로 고르지 않고 두 값을 모두 보여 주며 «확인 필요» |

확장 지점: 웹 화면(Streamlit)은 `cli.py`와 같은 위치에서 `extract → analyze → render`를 호출한다. 여러 법인 일괄 처리는 접수 단계에서 사업자등록번호로 PDF를 묶는 기능을 더한다. 엑셀 수정본 반영은 `Report`를 JSON으로 저장·재로드하는 경로를 쓴다.
